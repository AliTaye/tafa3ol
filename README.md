# مجتمع تفاعل | Tafa3ol

الموقع الرسمي: **https://tafa3ol.org/**

موقع عربي ثابت يعمل على **GitHub Pages** باستخدام **HTML + CSS + JavaScript ES Modules**، بدون Backend أو React أو أدوات بناء أو تثبيت حزم.

## فكرة التنظيم

- **`index.html`**: هيكل الصفحة والأقسام غير المتكررة؛ يبقي تصميم الصفحة العام وروابطها كما كان.
- **`data/`**: محتوى اللقاءات والأعضاء والأسئلة الشائعة والركائز. **هذا هو المجلد الذي تعدّله غالبًا.**
- **`components/`**: شكل البطاقات القابلة لإعادة الاستخدام. لا حاجة لتعديلها عند إضافة عنصر جديد.
- **`js/main.js`**: يرسم البطاقات أولًا ثم يفعّل التفاعلات.
- **`js/meetups.js`**: عدادات اللقاءات وفلترة الكل/القادمة/السابقة وحركة السلايدر.
- **`js/navigation.js`**: قائمة الجوال وظهور الشريط العلوي أثناء التمرير.
- **`js/faq.js`**: فتح إجابة واحدة وإغلاق البقية.
- **`js/animations.js`**: شريط التقدم وظهور/اختفاء العناصر عند التمرير.
- **`css/styles.css`**: الـCSS الأصلي من `index.html` دون تعديل قواعده.
- **`pics/`**: **نفس الصور الثماني بالأسماء الأصلية**.
- **`CNAME`**: اسم النطاق المخصص لـGitHub Pages؛ **لا تحذفه أو تغيّر محتواه**.


## إضافة لقاء جديد — لا تلمس HTML

1. افتح **`data/meetups.js`**.
2. أضف كائنًا جديدًا في بداية مصفوفة `meetups`، مع رقم `id` جديد غير مكرر.
3. احفظ الملف، وحدّث الصفحة في المتصفح. ستظهر البطاقة ويتغير العداد تلقائيًا.

```js
// مثال تعليمي فقط، لا تضفه الآن لأنه ليس لقاءً مُعلنًا.
{
  id: 5,
  title: 'عنوان اللقاء الخامس',
  description: 'وصف اللقاء',
  status: 'upcoming',     // upcoming أو past
  dateLabel: 'قريبًا',
  location: 'يُحدد لاحقًا',
  cover: null,           // مثال: 'pics/my-meetup.jpg'
  imageAlt: '',
  coverageUrl: null,     // بعد نشر التغطية: 'https://x.com/...'
  sponsor: null,         // أو { label: 'برعاية ...', icon: '☁️', style: 'sky' }
},
```

**مهم:** حالة اللقاء (`status`) مستقلة عن وجود تغطية (`coverageUrl`):

- `status: 'upcoming'` يعرض تصميم اللقاء القادم.
- `status: 'past'` يعرض تصميم اللقاء السابق.
- رابط التغطية **إن وُجد** يجعل البطاقة رابطًا يُفتح في تبويب جديد.
- بدون رابط، تكون البطاقة **غير قابلة للضغط**، حتى لو كان اللقاء سابقًا.
- لا تضف رابط تغطية على هيئة `<a>` بنفسك؛ `MeetupCard.js` يتصرف تلقائيًا.
- `cover` صورة اختيارية للقاء السابق، وتُستخدم الخلفية الأصلية عند عدم وجودها. أضف الصورة إلى `pics/` ثم استخدم مسارها النسبي الصحيح.
- في اللقاءات الموجودة، احتُفظ بعرض التاريخ والنصوص كما في النسخة المرفوعة؛ لا تُحوّلها إلى تواريخ آلية بدون مراجعة.

## تعديل الفريق أو الأسئلة أو الركائز

- **فريق تفاعل:** افتح `data/members.js`، ثم أضف `{ name, role, description, photo, initials, whatsappUrl, variant, mobileOrder, desktopOrder }`. استخدم `variant: 'member'` لعضو عادي؛ الأنواع `lead` و`advisor` و`vice` تخص **الشكل البصري فقط** ولا تُحدّد الترتيب. رقم الواتساب يجب أن يكون رابطًا مثل `https://wa.me/9665...`.
- **سؤال شائع:** افتح `data/faqs.js` وأضف `{ question: 'السؤال', answer: 'الإجابة' }`. تظل آلية فتح سؤال واحد فقط موجودة تلقائيًا.
- **ركيزة:** افتح `data/pillars.js` وأضف `{ title, description, footer, icon, variant, badge }`. الأيقونات الحالية: `meetups`, `whatsapp`, `audit`. الأنواع: `green`, `emerald`, `muted`.

## ترتيب أعضاء الفريق وتعديل بيانات رتاج ورائف

أضفنا **رتاج** و**رائف** كعضوين مبدئيين. لم نختلق لهما أرقام تواصل أو صورًا: `photo: null` يعرض الأحرف الأولى كبديل، و`whatsappUrl: null` يخفي زر التواصل حتى تضع رابطًا حقيقيًا. عدّل اسميهما الكاملين ووصفهما وصورهما في `data/members.js` حين تتوفر البيانات.

ترتيب **الكمبيوتر (1024px فأكثر)، من اليمين إلى اليسار في صف واحد من خمس بطاقات**: رتاج، أحمد، علي، محمد، رائف. ترتيب **الجوال، من الأعلى إلى الأسفل**: محمد، علي، أحمد، رتاج، رائف. الأجهزة المتوسطة تعرض ثلاثة أعمدة وتستخدم ترتيب الجوال إلى أن يصل العرض إلى 1024px.

للتحكم لاحقًا، عدّل رقمين فقط لكل عضو في `data/members.js`:

```js
mobileOrder: 4,    // ترتيب الجوال، الأول = 1
 desktopOrder: 1,  // ترتيب الكمبيوتر، الأيمن = 1
```

ترتيب الأعضاء مستقل عن `variant`؛ يتولى `js/main.js` فرز البطاقات حسب حجم الشاشة وتحريك **نفس عناصر الصفحة** دون إعادة إنشائها عند تغيير العرض، لتبقى حركة الظهور والروابط وترتيب لوحة المفاتيح متوافقة.

## معاينة الموقع محليًا

لأن المشروع يستعمل **ES Modules**، لا تفتح `index.html` بالنقر المزدوج باستخدام `file://`؛ استخدم خادم HTTP محليًا:

1. افتح **مجلد `tafa3ol`** كاملًا في **VS Code** (وليس ملف HTML منفردًا).
2. ثبّت إضافة **Live Server** إن لم تكن مثبتة.
3. اضغط بزر الفأرة الأيمن على `index.html` ثم **Open with Live Server** (أو استخدم زر **Go Live**).
4. افتح عنوان `http://127.0.0.1:5500/` الذي يعرضه Live Server. قد يختلف رقم المنفذ.
5. بعد تعديل `data/meetups.js` أو غيره، احفظ الملف ثم حدّث الصفحة إذا لم تتحدث تلقائيًا.

**لا تحتاج** `npm install` ولا `npm run build` ولا إعداد `.env` أو قاعدة بيانات. يلزم الاتصال بالإنترنت لتحميل **Tailwind CDN** وخطوط Google الموجودة أصلًا في الموقع.

## GitHub Pages

الناتج موقع ثابت كالموقع السابق. تبقى الملفات في جذر المستودع ويظل `index.html` نقطة الدخول. استخدم النشر الحالي من الفرع المحدد في إعدادات Pages، واحتفظ بملف `CNAME` دون تغيير. **لا حاجة إلى GitHub Actions أو Build جديد.**

لا تستبدل ملفات الموقع المنشور قبل معاينة النسخة الجديدة وفحصها. يُفضّل تجربة نسخة منفصلة ثم الدمج لاحقًا.

## الحفاظ على النسخة الأصلية والتحقق

أُعيد تقسيم البطاقات والبيانات دون تغيير المحتوى النصي أو صور ورُوابط النسخة المقدَّمة. فُصل الـCSS الأصلي دون تغيير قواعده، وحُفظت تفاعلات: قائمة الجوال، الشريط العلوي، شريط التمرير، فلاتر اللقاءات مع حركة 250ms، أسئلة FAQ، و`IntersectionObserver` لظهور العناصر.

في اختبارات DOM محلية مع Chromium معطّل الاتصال الخارجي، نجحت:

- ظهور **4 لقاءات (3 سابقة + 1 قادم)**، و**5 أعضاء**، و**3 أسئلة شائعة**، و**3 ركائز**.
- الروابط الثلاثة للقاءات السابقة، وبطاقة القادم غير القابلة للضغط.
- الانتقال بين جميع فلاتر اللقاءات، بما فيه الضغط المتتالي السريع.
- فتح سؤال، الانتقال لآخر، وإغلاق السؤال نفسه.
- فتح/إغلاق قائمة الجوال وتحديث `aria-expanded`.
- التحقق من تطابق النصوص والعناصر وكلاسات CSS الخاصة بالبطاقات مع نسخة HTML الأصلية.
- عدم وجود أخطاء JavaScript خلال الاختبارات الوظيفية المنفذة.

**ما لم يتم التحقق منه آليًا:** تحميل Tailwind CDN وخطوط Google من الإنترنت، ومطابقة لقطات الشاشة بكسلًا ببكسل في متصفح متصل، وجميع الحركات أثناء التمرير في بيئة نشر فعلية. لذلك قبل النشر النهائي جرّب الجوال والكمبيوتر، والتمرير للأعلى والأسفل، والسلايدر عند تغيير الحجم، والصور والروابط.
